# zh-paper-audit

中文论文文本自检。查**结构模板、引用严谨度、改写守恒**，零依赖，单文件。
当前版本 `2.4.0`（JSON schema `1`），95 项回归测试。

> **它不查 AIGC 检测分数。** 检测器算的是语言模型困惑度，和本工具输出的指标没有换算关系。
> 任何声称「用了能降到 X%」的工具都在骗人，包括本工具如果这么说的话。

```
python3 prescan.py 你的论文.md
```

Python 3.8+，只用标准库。没有 pip install，没有 API key，不上传任何内容。

## 它查什么，不查什么

| 查 | 怎么查 | 为什么值得查 |
|---|---|---|
| **中文序数骨架** | 正则匹配 其一/其二、第一/第二、首先/其次、一是/二是、(1)、①②、一、二、 | 最典型的"预喂结构"痕迹；主流中文检测工具都不查这一项（见下） |
| **无归属的权威** | 抽取"有学者认为""研究表明"等，判断有没有具体出处 | 答辩时第一个被追问的就是这个 |
| **首句同构** | 相邻段首句长度相近 + 共享结构标记词 | 拆掉"第一第二"之后最容易造出的新模板 |
| **稿内重复论证** | 句级相似度 ≥0.72 | 同一论点写两遍，改写时高频发生 |
| **断言强度** | 强/弱信号词表 | 把"有助于"改成"降低了"，是把推测说成事实 |
| **段落节奏** | 段长中位、连续段长度对称、句长 CV | 拆段拆过头会变成公众号体 |
| **五项改写守恒** | 前后稿对比 | 见下一节 |
| **文本体检** | 六项特征打分 | 不是论文就警告，避免阈值误用 |

| 不查 | 原因 |
|---|---|
| AIGC 检测分数 | 不公开算法，无换算关系，跨平台不可比 |
| "这段是不是 AI 写的" | 无法从文本形态反推生成过程 |
| 学术不端 | 代写、抄袭、数据造假不在文本形态层面可见 |

**关于「主流工具不查序数骨架」这件事**：这不是贬低同行，是实测结论。
`lieflat-less-ai-tone` 主动放弃该规则；`aigc-reduce` 的正则只认 `（1）` 阿拉伯数字括号。
拿 11 处「其一/第一」的文本跑这两个工具，均报 0 命中。这个仓库最初就是为了补这个洞。

## 五项守恒：改完有没有丢东西

这是本工具最实用的部分。改写论文最怕的不是改得不好，是**悄悄改丢了东西**。

```bash
python3 prescan.py 原稿.md --diff 改后.md
```

| 项 | 防的是什么 | 实测教训 |
|---|---|---|
| **数字 token** | 数据被改错、漏掉 | 20 个数据点的论文，改写后 56→56 零丢失 |
| **来源清单** | 引用整条消失 | 9 个来源全在位 |
| **论点强度** | 弱断言被加强 | "有助于降低" → "降低了"，属于把推测说成事实 |
| **论证覆盖** | 整段论证被删 | **只守数字守不住论证**：实测删掉 44 字一段，数字全对、标点全好 |
| **逻辑方向** | 因果被改成转折 | "因为 A 所以 B" → "B，然而 A"，句子相似度照样很高 |

第五项是最后加的，因为前四项全绿也拦不住它。

## 输出长什么样

摘要区按**确定性**分三级，不按严重程度——因为"先改哪个"比"一共有几项"重要。

```
## 摘要（先看这里）

**T1 结构模板**（3 项）— 先改这一级，检测器和人眼都认，改完再往下看

- 序数骨架 9 处（重度模板化）——结构模板，本文最重的痕迹
- 借来的权威 2 处无具体归属——答辩会被直接追问

**T2 节奏与标点**（3 项）— 改完 T1 再评估，不要和 T1 同时动手

- 段长中位 78.0 字，低于 academic 口径 120–350
- 破折号 3.90/千字（人类 0.80）
- 正文冒号 3.90/千字，疑似「标签：注脚」
```

完整输出见 [`examples/report-sample.md`](examples/report-sample.md)，
对应输入是 [`examples/sample.md`](examples/sample.md)。

对比报告的第一屏只有五行，全是是非题：

```
- ✅ 数字守恒：零丢失
- ✅ 来源守恒：全部在位
- ✅ 论证覆盖：9 段全部有对应
- ✅ 论点强度：未检出回退
- ✅ 逻辑方向：因果/转折关系未被改反
```

## 多轮返修：分清「本轮」和「累计」

改一版 → 去测 → 分数不够 → 再改。这是真实节奏，不是一次改完。

```bash
python3 prescan.py 原稿.md --diff v2.md --base v1.md
```

出来是两列：`本轮变化`（v1→v2 这一轮改了什么）和 `累计变化`（原稿→v2 一共改了多少）。

**为什么必须分开**：只看累计，会重复报第一轮早就解决的问题；只看本轮，发现不了
「改了三十处，结构骨架的净收益为零」——那种情况下再怎么改措辞，分数也不会动。

## 换学科：词表是外置的

`data/sources.*.txt` 一行一条机构/期刊/报告名，用于识别"这句话有没有出处"。
仓库自带三张种子表（商科 / 工科 / 学术），共 269 条。

```bash
# 默认加载 data/ 下全部词表，一般不用指定
python3 prescan.py 稿子.md

# 只想用自己领域的表（内置保底表始终保留）
python3 prescan.py 稿子.md --sources data/sources.tech.txt

# 看当前加载了什么
python3 prescan.py --list-sources
```

新建一个 `data/sources.医学.txt` 就会被自动加载，不用改代码。
**这 269 条是种子，不是全集**——按需补充，欢迎 PR。

段落长度口径同样可调：

```bash
python3 prescan.py 稿子.md --genre lab      # 工科实验报告，50–220 字/段
python3 prescan.py --list-genres
```

## 一条命令跑测试

```bash
python3 tests/test_prescan.py
```

95 项断言，覆盖的都是真实踩过的坑：破折号重复计数、标题段污染段长统计、
日期被吃掉、use/mention 误报、删整段不被发现、首句同构漏报、
文体口径判错、逻辑词表漏掉单字「但」、新增数字仍全绿、CLI 覆盖输入稿……

**改代码前先跑一遍。** 这类工具最隐蔽的失效不是"功能不对"，
是"曾经对的功能悄悄变不对"。

## 运行安全

- **输出不会覆盖输入。** `--out` / `--json` / `--txt` 指向输入稿、改后稿或本轮起点时直接拒绝执行。
- **写文件是原子的。** 先写同目录临时文件，成功后替换；失败时目标文件保持原样。
- **编码不静默乱码。** UTF-8（含 BOM）优先，UTF-16 BOM 识别，中文 Windows 的 GB18030 自动回退；都失败就报错。
- **JSON 带版本。** 存档记录 `tool_version` / `schema_version` / 关键阈值，几周后还能知道当时是用哪套口径跑的。

## 已知限制

诚实列出来，省得你踩到才发现：

- **阈值是种子值，不是通用标准。** 段长 120–350、覆盖率 0.45 相似度线、
  连接词配对下限 0.30，这些数值是在一篇 1552 字的商科案例分析上调出来的。
  样本量 n=1。换文体请用 `--genre`，换领域请补词表，并且**把结论当参考不当判据**。
- **逻辑方向只认连接词。** 不带连接词的语义反转——比如把「增长」改成「收缩」
  而句式不变——脚本认不出，只能通读。
- **文本体检有假阴性。** 技术文档（分节、长段、术语密集）会被判成论文。
  故意不修：误拦一篇真论文，比放过一篇技术文档代价大。
- **不判断"该不该改"。** 它只报事实。改不改、怎么改，取决于文体的必要性和作者意图。
- **不适用于非中文文本。** 所有判据都是中文语法的（顿号、序数、虚词）。

## 为什么不做「一键改写」

因为改写方向是矛盾的。

想要分数好看，最快的办法是加口语、加错别字、把论证拆成碎句——分数会降，
论文会废。反过来，正确改写需要理解论证，这件事没有通用脚本能做。

本工具停在"诊断"这一步，是刻意的。诊断可以自动化，改写不行。

如果确实要改，`docs/` 下面有三份材料：

- `docs/lessons.md` — **25 条踩坑记录**，每条都是真实发生过的
- `docs/citation-check.md` — 引用严谨度四查（比 AIGC 分数更容易被抓）
- `docs/no-drop-playbook.md` — 改完分数没降怎么办，三步归因

## 关于这个项目

起因是一篇商科案例分析论文的降重需求。做完发现两件事：

1. 主流中文工具对**序数骨架**集体失明，而这是最明显的模板痕迹；
2. 所有工具的失败都发生在**流程层**，不是检测层——改完没降怎么办、
   第二轮跟谁比、报告十项先改哪个，没有一个有答案。

所以这个仓库一半是检测脚本，一半是流程图和踩坑记录。后者可能更有用。

代码主体由 AI 助手（WorkBuddy）在人工逐轮审查下完成，
包括 95 项回归测试和多次对抗性自查。所有实测数据来自真实稿件。
